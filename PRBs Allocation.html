Foundation · Physical Resource Block

12 subcarriers × 14 symbols = 168 RE per PRB per slot

A PRB spans 12 subcarriers in frequency and 14 OFDM symbols in time. Each intersection is one Resource Element — the atomic unit of 5G NR scheduling and bit-level planning.

Why 12 subcarriers?

  • Divides into 2,3,4,6 — ideal for DMRS pilot patterns
  • At 15 kHz SCS: 180 kHz/PRB aligns with legacy UMTS
  • FFT sizes (512–4096) contain exact integer PRB counts
  • 12 enables up to 12 orthogonal OCC-spreading sequences (PUCCH F1)

Overhead sources in a PRB

  • DMRS — 4–12 REs/PRB/slot for channel estimation
  • PT-RS — 1–4 REs/PRB for phase noise tracking (mmWave)
  • SRS — 3–6 REs/PRB in sounding symbols (UL)
  • CSI-RS — variable density, DL reference signal
  • PDCCH CORESET — 3 of 12 REs per REG (25%) for control
Foundation · The time axis: what's fixed, what scales with numerology

Frame → Subframe → Slot — the timing scaffold every PRB grid sits inside

A radio frame (10 ms) and a subframe (1 ms) are always fixed, for every numerology. Only the slot — and therefore how many slots fit in a subframe — scales with SCS.

Numerology
1 radio frame = 10 ms = 10 subframes (always)
Zoom into subframe 3 → 1 slot(s), 14 OFDM symbols each

Every slot — regardless of numerology — is still 14 OFDM symbols (normal CP) × 12 subcarriers/PRB = 168 RE per PRB. Higher SCS doesn't add RE per PRB; it packs more slots into the same 1 ms, so each slot simply covers less absolute time.

Extended CP — the one exception

Only μ=2 (60 kHz) optionally supports Extended CP: 12 symbols/slot instead of 14, with a longer cyclic prefix per symbol. It trades a little RE budget for extra multipath tolerance — used in select deployments (e.g. some TDD/MBSFN-adjacent configs). Every other numerology uses Normal CP only.

Why this matters for PRB bit allocation

  • The 168 RE/PRB/slot figure from the previous slide is numerology-independent — it's a per-slot count, not a per-second one
  • Throughput scales because more slots fit per second at higher SCS (2000/slot-sec at 30 kHz vs 1000 at 15 kHz), not because each PRB carries more bits
  • PDCCH monitoring occasions, PRACH occasions and slot-format (D/S/U) all repeat on this same subframe/slot grid
  • All UL/DL channels in a cell share one numerology per BWP — mixed numerologies live in different BWPs

Reading the table (ShareTechNote's rule of thumb)

Channel BW ≈ [N_RB × 12 × SCS] + [2 × Guardband]

Numbers worth memorising

  • 12 subcarriers/PRB — fixed for every numerology, every band
  • 273 PRB — the common FR1 macro-cell max (100 MHz @ 30 kHz SCS)
  • 275 PRB — the absolute spec ceiling N_grid,max (TS 38.211 §4.4.2) for any single NR carrier, any numerology
  • 264 PRB — the common FR2 max (200 MHz @ 60 kHz, or 100 MHz @ 120 kHz)
  • Guardband exists so out-of-band emissions don't leak into neighbouring channels — it shrinks (relatively) as SCS grows
Foundation · The nuance behind "which PRB" — indexing is always relative to something

Bandwidth Part & PRB Indexing — Point A, CRB, BWP, and why "PRB 0" moves

Every canvas so far has shown "PRB 0, 1, 2…" — but PRB 0 relative to what? This is the single biggest source of confusion when reading a real resource grid, so it gets its own slide.

Point A (CRB 0, k=0)
Common Resource Block (CRB) grid — carrier bandwidth, 106 PRB shown
Initial BWP0 — CRB 0–51 (52 PRB) — local PRB 0 = CRB 0
Dedicated BWP1 — CRB 10–105 (96 PRB) — local PRB 0 = CRB 10
SSB — 20 PRB @ offset 8
CORESET0 — 48 PRB from CRB 0

Point A & the CRB grid

  • Point A is a frequency reference broadcast per cell — the lowest subcarrier of CRB 0
  • Common Resource Blocks (CRB) are numbered 0, 1, 2… upward from Point A, for one specific numerology
  • Every other grid (carrier, BWP) is ultimately anchored back to this one reference point

Bandwidth Part (BWP)

  • A contiguous slice of CRBs with one numerology — up to 4 DL + 4 UL BWPs configured, only 1 active per direction at a time
  • PRB indices in a DCI grant are relative to the active BWP's start, not to Point A — this is the "gotcha"
  • The initial BWP (used before RRC configures others) is derived from CORESET0's bandwidth

SSB & CORESET0 placement

  • SSB position: coarse offsetToPointA (CRB-level) + fine k_SSB (subcarrier-level) — found via the GSCN raster, independent of any BWP
  • CORESET0 size/offset comes from a 4-bit index in the MIB, looked up in 38.213 Tables 13-1…13-10, positioned relative to the SSB
  • SSB and CORESET0 usually overlap or sit adjacent — the UE needs both before it can read SIB1

UL vs DL — who transmits what, and why

5G NR is fundamentally a half-duplex negotiation in TDD: every physical channel and reference signal belongs to exactly one direction. This is the direction key you'll see colour-coded throughout the rest of the deck.

Key insight: every slot is a negotiation

Format 0 — Key Properties

  • Sequence: L=839 Zadoff-Chu, SCS=1.25 kHz, 1 symbol (800 µs) per occasion
  • Coverage: ~14.5 km max cell radius — the original LTE-style format
  • Occupies: ≈6 PRBs at the 15 kHz reference grid, always FR1
  • No channel coding, no modulation table — detected by correlation, not demodulation

Random access in 4 steps (contention-based)

  • Msg1 — PRACH: UE sends preamble (this channel)
  • Msg2 — RAR: gNB replies on PDSCH, addressed by RA-RNTI, with timing advance + UL grant
  • Msg3 — PUSCH: UE sends RRC Setup Request using the granted resources
  • Msg4 — PDSCH: gNB resolves contention, UE gets its C-RNTI
  • 2-step (MsgA/MsgB): PRACH + PUSCH sent together for lower latency
▼ RX — gNB Preamble Detection
  • Correlate received symbol against all 64 root/shift hypotheses
  • Peak above threshold → preamble index + round-trip delay (→ Timing Advance)
  • RA-RNTI = 1 + s_id + 14·t_id + 14·80·f_id + 14·80·8·ul_carrier_id
  • gNB schedules RAR (Msg2) on PDSCH addressed to that RA-RNTI

REG and CCE structure

  • REG = 1 PRB × 1 symbol = 12 RE
  • DMRS in REG: k=1,5,9 → 3 DMRS + 9 data RE per REG
  • CCE = 6 REGs = 54 data + 18 DMRS RE = 72 total RE
  • QPSK: 54×2 = 108 coded bits per CCE
  • AL×CCE: AL16 = 16×54 = 864 data RE = 1728 coded bits
  • DMRS overhead: 3/12 = 25% per REG (fixed, non-configurable)
▼ RX — Blind DCI Detection
  • UE monitors CSS + USS search spaces
  • Tries all candidate CCE offsets × all ALs
  • QPSK demod → soft LLR → Polar decode
  • CRC check with own RNTI → accept if passes
  • Up to 44 PDCCH candidates per slot (spec limit)
  • Failure → DCI miss; wrong decode → false alarm

CORESET & Search Space — where the UE actually looks for its DCI

CORESET frequency resource & REG mapping

  • Frequency mask: a bitmap over groups of 6 RBs — up to 45 bits ⇒ up to 270 RB coverage. CORESET0 is the exception: size/position come from a lookup table, not a bitmap
  • Duration: 1–3 OFDM symbols, set independently of the bitmap
  • REG bundle: 2, 3 or 6 REGs grouped for joint channel-estimation interpolation
  • Non-interleaved mapping keeps REGs contiguous (pairs with beamforming); interleaved spreads them for frequency diversity (typical for broadcast-style CSS)

How this differs from the basic PDCCH slide

The PDCCH slide showed how many RE a CCE/AL costs. This one is about which RBs those RE are drawn from (CORESET's mask) and when the UE bothers to check (search space).

A bitmap of ⌈N/P⌉ bits — 1 bit per RBG, allocating whole RBGs at once, letting a grant scatter across non-contiguous chunks of the BWP.

Which one does PDSCH/PUSCH actually use?

Both formats exist in the spec; the DCI's "resource allocation" field (or a fixed RRC-configured choice) tells the UE which interpretation applies. Type 1 is simple and common for scheduling one clean chunk; Type 0 gives the scheduler more flexibility to pack multiple UEs into the same slot around each other's allocations.

MIMO Layers & DMRS Ports — why more layers don't cost more RE

A layer is a spatial stream of data. A DMRS port is what the receiver uses to estimate the channel for that layer. Ports sharing a CDM group sit on the exact same REs, separated purely by an orthogonal cover code (OCC) — not by using extra spectrum.

The two orthogonality axes

  • Frequency-domain OCC (FD-OCC): length-2 code across paired REs within one CDM group — separates ports within a group without using extra REs
  • Time-domain OCC (TD-OCC): only available when a second DMRS symbol is added — a further length-2 code across the two symbols, doubling the port count again
  • CDM groups (λ): separated purely by which REs they occupy (comb pattern) — the actual "spectrum-costing" dimension

Going from rank 1 → 2 costs zero extra RE (same CDM group, OCC-separated). Going to rank 3+ activates the second CDM group — the RE pattern shown in the PDSCH/PUSCH slides jumps from 6→12 DMRS RE/PRB exactly at this point.

Ties back to the design principle

This is the mechanism behind the summary slide's claim that "DMRS enables both channel estimation AND layer orthogonality — zero extra RE cost for multi-layer support." OCC is why that's true: more ports share, rather than add to, the RE budget.

Spectral efficiency by channel and modulation (bits per RE)

Peak PUSCH (100 MHz, 30 kHz SCS)

  • 273 PRBs (fixed-PRB table, slide 3), 256-QAM, R=0.926, rank 1
  • 162 data RE/PRB × 273 = 44,226 total RE/slot
  • 44,226 × 8 × 0.926 ≈ 327,627 info bits/slot (0.5 ms → 2000 slots/s)
  • 327,627 × 2000 ≈ 655 Mbps (rank 1) · × 4 layers ≈ ~2.6 Gbps

Peak PDSCH (100 MHz, 30 kHz SCS)

  • 273 PRBs, 256-QAM, R=0.926, same RE budget as PUSCH
  • ≈655 Mbps per spatial layer (rank 1)
  • Up to 8 DL layers supported by spec
  • × 8 layers (rank 8) ≈ ~5.2 Gbps

Three core design principles behind the RE budget

Every overhead serves two masters. DMRS enables both channel estimation AND layer orthogonality via CDM groups — zero extra RE cost for multi-layer support.

Overhead scales with channel rank. DMRS occupies 6 RE/PRB (rank 1–2) or 12 RE/PRB (rank 3–4) for Type 1 — adaptive to MIMO mode.

LDPC vs Polar split. LDPC for long data blocks (PUSCH/PDSCH), Polar for short control blocks (DCI/UCI/MIB) — each optimal in its block-length regime.

OFDM: frequency-domain REs become time-domain samples

Each OFDM symbol starts from subcarrier-domain complex values. An IFFT generates a discrete-time waveform containing all occupied subcarriers simultaneously.

Active subcarriers 32 Phase pattern

Frequency-domain view

Time-domain view after IFFT

The IFFT converts N subcarrier values into N time-domain samples. The OFDM sample rate is tied to the chosen FFT size and sampling configuration.
OFDM · Step 2 of 2

Cyclic prefix insertion — copy the tail, put it in front

The CP turns a linear convolution channel into a circular-convolution model over the useful symbol interval, provided the CP is sufficiently long for the relevant channel delay spread.

CP length 12 samples

1 · Take the tail

The final CP-length samples of the IFFT output are selected.

2 · Prepend

Those samples are copied to the beginning of the transmitted OFDM symbol.

3 · Receiver

After CP removal, FFT processing recovers the subcarrier-domain symbol with reduced inter-symbol interference when the design assumptions hold.

Why higher SCS shortens symbols

  • Subcarrier spacing increases as 15 × 2^μ kHz.
  • Useful symbol duration approximately scales as the reciprocal of SCS.
  • NR can therefore use shorter symbols for higher-delay/Doppler environments, while CP must still cover the relevant propagation delay spread.

PRACH does not reuse the same narrow data-channel resource shape as PUSCH. It uses a dedicated preamble design and configured occasion.
